# product-hub · 一个人的产品工作台

把散落在 markdown 里的产品思考，变成一屏能看、能讲的可视化界面。

它不连数据库，**你写的 markdown 文件就是全部数据**。改文档 → 刷新页面 → 工作台跟着变。

## 它解决什么

产品同学真正痛苦的不是「没东西可写」，而是写完之后：

- 文档躺在文件夹里没人看，决策过了三个月就没人记得为什么
- 想跟人讲清楚产品，得临时拼一堆截图和文档
- 需求池、迭代流程、决策日志各在一处，互相之间对不上

product-hub 把这些收进一个工作台：内容仍是 markdown，展示交给它。

## 核心思路

**加一个目录 = 加一个板块。** 在 `content/` 下建个目录放 md，工作台下次启动就多一个板块，零代码改动。

分层由文件里的字段决定，不依赖目录层级——调整归类只改字段，不用挪文件。

## 快速开始

```bash
npm install
npm run gen:data   # 生成 src/data/generated.json（dev/build 会自动跑）
npm run dev
```

打开后你会看到一份**示例内容**（产品概览、需求池、迭代流程、决策日志、愿景）。
把它换成你自己的产品即可。

## 内容结构

```
content/
├── 产品叙事/          # 产品概览（定位、使命愿景、关键问题、边界）
├── 需求池/            # 一条需求 = 一个 "## REQ-xxx · 标题" 小节
├── 迭代流程/          # 四步循环与出口条件
├── 决策日志/          # 只记「为什么这么定」
└── 灵感库/            # 愿景与关键问题（驱动「终态目标」视图）
```

内置板块（不来自 content，由组件直接实现）：工作台首页、终态目标、产品概览、核心结构、产品现状、需求池、推进路线、身份资产、原型库、文档地图。

## 接你自己的数据源

工作台可以额外挂载两个**只读**数据源，都在 `config/sources.mjs` 里配：

| 配置 | 提供什么 | 不配会怎样 |
| --- | --- | --- |
| `DOCS` | 文档地图（含健康度告警）、身份资产、原型库、mermaid 流程 | 这几个板块为空 |
| `APP` | 产品现状：页面清单、模块规模、接口清单（读 manifest / pages / api） | 产品现状隐藏 |

两者都只读，且都不是必需——只写 `content/` 也能用。
目录不存在时会自动降级，不会报错。

想接真实产品：改 `config/sources.mjs` 里的 `DOCS` / `APP` 指向你的文档仓库与客户端仓库，
并按你的产品结构填 `APP_MODULES` / `PAGE_LABELS` / `APP_API_LABELS`（只是命名翻译层，不填也能跑）。

## 技术栈

Vue 3（`<script setup>`）+ TypeScript + Vite + Tailwind CSS 4 + `@phosphor-icons/vue` + mermaid。
